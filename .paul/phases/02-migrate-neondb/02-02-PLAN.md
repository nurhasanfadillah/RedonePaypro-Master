<objective>
## Goal
Buat 6 Vercel Serverless Function files di `/api/` yang menggantikan seluruh operasi Supabase PostgREST dengan Drizzle ORM queries ke NeonDB.

## Purpose
Ini adalah backend layer — frontend tidak boleh mengakses NeonDB langsung. Setiap fungsi di sini menerima HTTP request dari `dataService.ts`, query NeonDB via Drizzle, dan return JSON response.

## Output
- `api/employees.ts` — CRUD karyawan + dependency check
- `api/components.ts` — CRUD komponen + dependency check
- `api/production-logs.ts` — CRUD log produksi + delete-all
- `api/payments.ts` — CRUD pembayaran + delete-all
- `api/auth.ts` — login
- `api/users.ts` — user management + update password
</objective>

<acceptance_criteria>

## AC-1: Employee Endpoint Berfungsi
```gherkin
Given api/employees.ts ter-deploy
When GET /api/employees dipanggil
Then returns JSON array of Employee objects (id, name, address)
When POST /api/employees dipanggil dengan body Employee
Then data tersimpan/terupdate di NeonDB, returns { ok: true }
When DELETE /api/employees?id=xxx dipanggil
Then employee dan app_user terkait terhapus
```

## AC-2: Auth Endpoint Berfungsi
```gherkin
Given api/auth.ts ter-deploy
When POST /api/auth dengan { username: "admin", password: "admin123" }
Then returns UserAccount object (username, role, fullName, employeeId)
When credentials salah
Then returns null (HTTP 200 dengan body null)
```

## AC-3: Semua Numeric Fields Dikembalikan sebagai Number
```gherkin
Given data di NeonDB dengan numeric columns (price, priceSnapshot, total, amount)
When API endpoint dipanggil
Then response JSON berisi angka (number), bukan string
```

## AC-4: Error Handling Konsisten
```gherkin
Given request dengan method yang tidak didukung
When dipanggil
Then returns HTTP 405 dengan { error: "Method not allowed" }
Given query gagal
When terjadi exception
Then returns HTTP 500 dengan { error: message }
```

  <name>Task 1: Buat api/employees.ts + api/components.ts</name>
  <files>api/employees.ts, api/components.ts</files>
  <action>
    **Pola umum untuk semua API files:**
    - Import: `VercelRequest`, `VercelResponse` dari `@vercel/node`
    - Import: `db` dari `../db/index`
    - Import tables dan helpers dari `drizzle-orm`: `eq`, `asc`, `desc`, `count`
    - Wrap seluruh handler dalam try/catch, return 500 jika error
    - numeric fields (price, amount, priceSnapshot, total) harus di-`parseFloat()` atau `Number()` sebelum dikirim ke client

    **api/employees.ts — menangani:**
    - `GET /api/employees` → select all, order by id asc
    - `GET /api/employees?checkDeps=1&id=xxx` → count production_logs + payments untuk employee id
    - `POST /api/employees` → upsert via `onConflictDoUpdate({ target: employees.id, set: { name, address } })`
    - `DELETE /api/employees?id=xxx` → hapus app_users dulu (foreign key), lalu hapus employees

    Response untuk checkDeps: `{ hasDependencies: boolean, details: { production: number, payments: number } }`

    **api/components.ts — menangani:**
    - `GET /api/components` → select all, order by id asc, pastikan `price` di-parseFloat()
    - `GET /api/components?checkDeps=1&id=xxx` → count production_logs untuk component id
    - `POST /api/components` → upsert via `onConflictDoUpdate({ target: components.id, set: { name, price } })`
    - `DELETE /api/components?id=xxx` → hapus component

    Response untuk checkDeps: `{ hasDependencies: boolean, details: { production: number } }`

    Avoid: Jangan lupa hapus `app_users` sebelum `employees` di DELETE employee (foreign key constraint).
    Avoid: `numeric` dari Drizzle/PostgreSQL returns string — selalu konversi ke Number sebelum return.
  </action>
  <verify>

    - `curl http://localhost:3000/api/employees` → returns []
    - `curl http://localhost:3000/api/components` → returns []
    - TypeScript tidak ada compile error di kedua file
  </verify>

<task type="auto">
  <name>Task 2: Buat api/production-logs.ts + api/payments.ts</name>
  <files>api/production-logs.ts, api/payments.ts</files>
  <action>
    **api/production-logs.ts — menangani:**
    - `GET /api/production-logs` → select all, order by created_at desc
      Map hasil: pastikan `priceSnapshot` dan `total` di-parseFloat()
      Alias kolom sesuai dengan type ProductionLog (camelCase sudah ditangani Drizzle schema)
    - `POST /api/production-logs` → upsert: `onConflictDoUpdate({ target: productionLogs.id, set: { date, employeeId, componentId, qty, priceSnapshot, total } })`
    - `DELETE /api/production-logs?id=xxx` → hapus by id
    - `DELETE /api/production-logs?all=1` → hapus semua via `db.delete(productionLogs)` (tanpa WHERE)

    **api/payments.ts — menangani:**
    - `GET /api/payments` → select all, order by created_at desc
      Pastikan `amount` di-parseFloat()
    - `POST /api/payments` → upsert: `onConflictDoUpdate({ target: payments.id, set: { date, employeeId, amount, type, note } })`
    - `DELETE /api/payments?id=xxx` → hapus by id
    - `DELETE /api/payments?all=1` → hapus semua via `db.delete(payments)`

    Avoid: Saat DELETE tanpa kondisi (`db.delete(table)` tanpa `.where()`), Drizzle secara default menghapus SEMUA baris — ini intentional untuk deleteAll operation.
    Avoid: Jangan mix up query params: `?id=` untuk single delete, `?all=1` untuk delete all.
  </action>
  <verify>
    - TypeScript tidak ada compile error
    - `curl -X DELETE http://localhost:3000/api/production-logs?all=1` → returns { ok: true }
  </verify>
  <done>AC-1 dan AC-3 satisfied: production-logs dan payments endpoints berfungsi, numeric fields sebagai Number</done>
</task>

<task type="auto">
  <name>Task 3: Buat api/auth.ts + api/users.ts</name>
  <files>api/auth.ts, api/users.ts</files>
  <action>
    **api/auth.ts — menangani:**
    - `POST /api/auth` body: `{ username, password }`
    - Query: select dari `appUsers` WHERE username = ? AND password = ?
    - Jika ada: return `{ username, password, role, employeeId, fullName }` (map dari DB columns)
    - Jika tidak ada: return `null` (HTTP 200)

    **api/users.ts — menangani:**
    - `GET /api/users` → select all users, map ke UserAccount shape
    - `GET /api/users?employeeId=xxx` → select user WHERE employeeId = xxx, return satu user atau null
    - `POST /api/users` body: UserAccount → upsert `onConflictDoUpdate({ target: appUsers.username, set: { password, role, employeeId, fullName } })`
      Jika error duplicate key: return HTTP 409 dengan `{ error: "Username '...' sudah digunakan." }`
    - `PUT /api/users?action=password` body: `{ username, oldPass, newPass }`
      1. Verify old password: select user WHERE username = ? AND password = oldPass
      2. Jika tidak match: return HTTP 400 `{ error: "Password lama salah." }`
      3. Jika match: update password, return `{ ok: true }`
    - `DELETE /api/users?employeeId=xxx` → hapus user WHERE employeeId = xxx

    UserAccount shape yang dikembalikan:
    ```typescript
    { username, password, role, employeeId: row.employeeId, fullName: row.fullName }
    ```

    Avoid: localStorage tidak boleh disentuh di API route — itu tanggung jawab frontend di dataService.ts.
    Avoid: Password TIDAK di-hash (consistent dengan implementasi existing yang memang plaintext).
  </action>
  <verify>
    - `curl -X POST http://localhost:3000/api/auth -H "Content-Type: application/json" -d '{"username":"admin","password":"admin123"}'`
      → Jika belum ada user admin, returns null. Setelah user di-seed, returns user object.
    - TypeScript tidak ada compile error
  </verify>
